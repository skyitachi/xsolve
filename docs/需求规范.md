# xsolve 需求提交规范

> 给 AI（或协作者）提需求时对照填写，能显著减少理解偏差与返工。
> 适用于：家长模式 / 学生模式 / 通用基建（DB、工具、前端、后端）的任何改动。

## 一、为什么需要这份规范

xsolve 有几处**结构性特点**，需求里不说清就会跑偏：

- **双模式架构**：student 模式有严格约束（不给答案、不主动讲解），parent 模式才讲解。模式搞错，行为就加错地方。
- **三层 prompt 机制**：`config.js` 硬编码 → DB `prompt_versions` 版本管理 → 活跃版本。改 `config.js` 不会自动生效，必须同步 DB。
- **工具白名单**：`ALLOWED_TOOLS` 只放了 `mcp__tutor__*`，**没有 Read/Write**——agent 不能自己读写文件，能力型需求基本都要落成 MCP 工具。
- **前端 SSE + ui_event 驱动**：产物怎么展示（文本/卡片/弹窗/iframe）必须说清，否则前端要返工。

## 二、需求模板（复制填写）

```
【目标模式】student / parent / 两者 / 通用基建
【改动落点】prompt 行为 / 新增或改 MCP 工具 / 前端 UI / DB 数据 / 后端逻辑
【触发场景】用户说/做什么时触发（给 1-2 句真实对话样例）
【期望行为】agent 做什么（调哪个工具、回什么、不能做什么）；
           用户看到什么（纯文本/工具卡片/弹窗/iframe）
【数据】读什么、写什么、是否持久化、是否要 DB 迁移
【环境】是否有外网（影响 CDN/视觉模型）、部署目标
【验收】怎么算做完（1 个可测场景）
```

## 三、本项目特有的 4 个陷阱（务必在需求里点明）

### 1. 模式要说清
student 模式：绝对不主动给答案/思路/步骤，只在学生明确提问时以引导为主回答。
parent 模式：可主动分析、讲解考点、给辅导策略。
需求不写模式，可能把讲解能力加进学生模式，违反核心约束。

### 2. 改 prompt ≠ 改 config.js
- prompt 存在 DB `prompt_versions` 表，`getActivePromptVersion(mode)` 读活跃版本。
- `seedPromptVersions()` **只在表为空时**执行，现网 DB 已有数据。
- 改了 `config.js` 的 `SYSTEM_PROMPT_*` 后，必须二选一让 DB 生效：
  - 跑 `node backend/scripts/upgrade-parent-prompt.mjs`（家长模式，自动 insert+activate），或
  - 在 `/prompts.html` 管理页新建版本并激活。
- 需求涉及 prompt 时，注明"是否要同步 DB"。

### 3. "让 agent 做某事" 通常 = 新增 MCP 工具
本项目 `ALLOWED_TOOLS` 只白名单了 MCP 工具，没有 Read/Write/Edit。所以：
- 生成图、导出文件、查外部数据、调外部 API……都要落成 `backend/mcp-tools.js` 里的 `tool(...)`，并加进 `config.js` 的 `ALLOWED_TOOLS`。
- 工具产物需要展示给用户时，用 `session.emit('ui_event', { type, ... })` 通知前端，前端在 `frontend/js/chat.js` 的 `handleUiEvent` 里渲染。

### 4. 产物怎么展示
前端用 SSE 推 `sdk_message` / `ui_event`。常见展示方式：
- 纯文本/Markdown：assistant 消息流式渲染（`renderAiBlock`，支持 `$...$` KaTeX）。
- 工具调用卡片：自动渲染（`addToolCallCard`），只需在 `TOOL_LABELS` 加中文名。
- 弹窗确认：`ui_event` 的 `problem_proposed` / `delete_proposed` 类型。
- 内嵌交互：`ui_event` + 自定义卡片（如 `diagram_generated` 用 iframe）。

需求里说清"用户最终看到什么、怎么交互"。

## 四、正反对比示例

以「集成 jsxgraph-step-diagram」为例：

**❌ 模糊**
> 把 jsxgraph-step-diagram 集成进来。

后果：可能去放 `.claude/skills/`，但本项目根本不走 skill 发现，白做；也不知道给哪个模式、怎么展示。

**✅ 清楚**
> 在**家长模式**集成 jsxgraph-step-diagram。
> 【触发】家长说"按步骤画出来/分步演示"时。
> 【行为】agent 调用 `generate_step_diagram` 工具生成交互式 HTML。
> 【展示】在聊天里**内嵌 iframe 卡片**，可点「下一步」。
> 【边界】默认不画坐标轴；几何作图不需要，函数图像可由模型开 `show_axis`。
> 【同步】改动要同步 DB parent prompt（跑 upgrade 脚本）。
> 【验收】家长模式发"分步画等边三角形尺规作图"，聊天里出现可交互卡片。

## 五、其他提醒

- **兼容双端**：UI 改动要兼容 PC 和移动端（触控/键盘），见 `AGENTS.md`。
- **离线/CDN**：若部署环境无外网，涉及 CDN（如 jsxgraph 的 jsdelivr）的需求要说明，提前本地化。
- **DB 迁移**：改 schema 要考虑已有数据，必要时写迁移脚本（参考 `backend/scripts/backfill-prompt-version.mjs`）。
- **遗留代码**：`backend/routes.js` 是死代码（`handleRequest` 无引用），实际路由在 `backend/app.js` + `controllers/`，别改错地方。
